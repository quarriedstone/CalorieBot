# CalorieBot

Telegram-бот для учёта КБЖУ. Бот распознаёт блюда по текстовому описанию через DeepSeek API и ведёт дневную таблицу калорий, белков, жиров и углеводов.

## Возможности

1. **Цель КБЖУ** — пользователь задаёт дневную норму одним сообщением в виде `белки/жиры/углеводы` (например, `120/60/220`); калории считаются по формуле Б×4 + Ж×9 + У×4. Разделители — `/`, пробел или запятая.
2. **Добавление блюда** — пользователь пишет, что съел, и бот добавляет запись в активную заметку. Если указан точный состав, бот считает КБЖУ сам, иначе подбирает через DeepSeek API (в ответе модели есть флаг `found` и оценка уверенности `confidence`). Если ввод не является продуктом или продукт неизвестен, бот отвечает «Продукт не найден» и ничего не записывает.
3. **Таблица заметки** — бот формирует таблицу блюд и КБЖУ за заметку и считает остаток или превышение относительно цели.
4. **Новая заметка** — кнопка «📝 Новая заметка» в главном меню создаёт новую заметку с новой таблицей (цель берётся из сохранённой). За одну дату может быть несколько заметок.
5. **Выбор заметки** — кнопка «📂 Выбрать заметку» показывает последние 5 заметок, из которых можно выбрать заметку и посмотреть её КБЖУ. Открытая заметка становится активной: следующие продукты сохраняются в неё.
6. **Удаление продукта** — кнопка «🗑 Удалить продукт» показывает нумерованный список блюд активной заметки, а кнопки-номера идут в обратном порядке (последняя запись — первой). Если блюд больше 8, снизу появляется широкая кнопка «Далее» для перехода к более ранним записям.
7. **Удаление заметки** — на карточке заметки есть кнопка «🗑 Удалить заметку»: бот показывает число записей и итог и удаляет заметку только после подтверждения («✅ Удалить» / «❌ Отмена»). Записи удаляются вместе с заметкой, после чего бот сообщает об удалении и предлагает выбрать заметку заново из списка. Пока заметка не выбрана, продукты не добавляются.

## Форматы ввода еды

| Сообщение | Как понимается |
| --- | --- |
| `круассан 60` | 60 грамм круассана. КБЖУ подбирает DeepSeek под указанный вес. |
| `круассан 60 10,15,40` | 60 грамм круассана, а `10,15,40` — точные Б/Ж/У **на 100 грамм** продукта. Бот пересчитывает на 60 г и считает калории по 4/9/4 ккал на 1 г Б/Ж/У. Без обращения к API. |
| `овсянка на молоке, 300 ккал` | Свободное описание. КБЖУ подбирает DeepSeek; явно указанные калории учитываются. |
| `Экспонента 30 0 6.5` | Б/Ж/У указаны **на всю порцию** (без веса): 30 г белка, 0 г жира, 6,5 г углеводов. Калории — по 4/9/4 ккал на 1 г. Без обращения к API. |

Разделители в списке Б/Ж/У — запятая или пробел (`60 10,15,40` и `60 10 15 40` равнозначны).

В формате `название Б/Ж/У` вес не указывается — бот считает, что числа относятся к съеденной порции целиком.

Скобки вокруг чисел не мешают: `Экспонента (30/0/6,5)` и `Экспонента 30/0/6,5` равнозначны (30 г белка, 0 г жира, 6,5 г углеводов). Если числа целиком в скобках, вес не подразумевается — `Экспонента (30 0 6,5)` читается как Б/Ж/У на порцию, а не как «30 г продукта».

## Технологии

- Python 3.12
- [Poetry](https://python-poetry.org/) — управление зависимостями
- [aiogram 3](https://aiogram.dev/) — Telegram Bot API
- [pydantic](https://docs.pydantic.dev/) — доменные модели
- [dependency-injector](https://python-dependency-injector.ets-labs.org/) — DI-контейнер
- [OpenAI SDK](https://platform.deepseek.com/) — клиент к DeepSeek API (Responses API, модель `deepseek-flash`)
- SQLite (aiosqlite) — хранение данных
- Docker

## Локальный запуск

```bash
# 1. Создать .env из примера и заполнить токены
cp .env.example .env

# 2. Установить зависимости
poetry install

# 3. Запустить бота
poetry run python -m bot.main
```

> Если Poetry не установлен, а в проекте уже есть виртуальное окружение `.venv`:
> ```bash
> .venv\Scripts\python -m pip install poetry   # Windows
> .venv\Scripts\poetry install
> .venv\Scripts\poetry run python -m bot.main
> ```

## Запуск через Docker

```bash
# 1. Создать .env из примера и заполнить токены
cp .env.example .env

# 2. (опционально, для воспроизводимых сборок) зафиксировать зависимости
poetry lock

# 3. Собрать и запустить
docker compose up -d --build
```

Данные (SQLite) хранятся в Docker volume `bot_data`.

## Структура проекта

```
bot/
  main.py                    # точка входа: контейнер, middleware, polling
  config.py                  # настройки из переменных окружения (.env)
  container.py               # Container — сборка адаптеров и сервисов
  domain/                    # бизнес-логика
    models.py                # Macros, Food, DayInfo, DaySummary, AddFoodResult
    parsing.py               # разбор цели и форматов ввода, пересчёт КБЖУ
    services.py              # UserService, DayService, FoodService
  infrastructure/            # адаптеры к внешним зависимостям
    db.py                    # SQLite (aiosqlite)
    deepseek.py              # DeepSeek API
  presentation/              # работа с Telegram
    handlers.py              # Router и обработчики сообщений/callback'ов
    keyboards.py             # клавиатуры
    formatting.py            # форматирование вывода
    middleware.py            # инъекция сервисов из контейнера
```
