# CalorieBot

Telegram-бот для учёта КБЖУ. Бот распознаёт блюда по текстовому описанию через DeepSeek API и ведёт дневную таблицу калорий, белков, жиров и углеводов.

## Возможности

1. **Цель КБЖУ** — пользователь задаёт дневную норму одним сообщением: `калории/белки/жиры/углеводы` (например, `1800/120/60/220`) либо только `белки/жиры/углеводы` (например, `120/60/220`) — тогда калории считаются по формуле Б×4 + Ж×9 + У×4. Разделители — `/`, пробел или запятая.
2. **Добавление блюда** — пользователь пишет, что съел, и бот добавляет запись в текущий день. Если указан точный состав, бот считает КБЖУ сам, иначе подбирает через DeepSeek API.
3. **Таблица дня** — бот формирует таблицу блюд и КБЖУ за день и считает остаток или превышение относительно цели.
4. **Новый день** — кнопка «📅 Новый день» создаёт новый день с новой таблицей (цель берётся из сохранённой). За одну дату может быть несколько дней.
5. **История** — кнопка «📜 История» показывает последние 5 дней, из которых можно выбрать день и посмотреть его КБЖУ. Открытый день становится активным: следующие продукты сохраняются в него (вернуться к текущему дню — кнопка «↩️ Текущий день»).

## Форматы ввода еды

| Сообщение | Как понимается |
| --- | --- |
| `круассан 60` | 60 грамм круассана. КБЖУ подбирает DeepSeek под указанный вес. |
| `круассан 60 10,15,40` | 60 грамм круассана, а `10,15,40` — точные Б/Ж/У **на 100 грамм** продукта. Бот пересчитывает на 60 г и считает калории по 4/9/4 ккал на 1 г Б/Ж/У. Без обращения к API. |
| `овсянка на молоке, 300 ккал` | Свободное описание. КБЖУ подбирает DeepSeek; явно указанные калории учитываются. |

Разделители в списке Б/Ж/У — запятая или пробел (`60 10,15,40` и `60 10 15 40` равнозначны).

## Технологии

- Python 3.12
- [Poetry](https://python-poetry.org/) — управление зависимостями
- [aiogram 3](https://aiogram.dev/) — Telegram Bot API
- [pydantic](https://docs.pydantic.dev/) — доменные модели
- [dependency-injector](https://python-dependency-injector.ets-labs.org/) — DI-контейнер
- [OpenAI SDK](https://platform.deepseek.com/) — клиент к DeepSeek API (совместимый с OpenAI)
- SQLite (aiosqlite) — хранение данных
- Docker

## Локальный запуск

```bash
# 1. Создать .env из примера и заполнить токены
cp .env.example .env

# 2. Установить зависимости
poetry install

# 3. Запустить бота
poetry run python -m bot.main
```

> Если Poetry не установлен, а в проекте уже есть виртуальное окружение `.venv`:
> ```bash
> .venv\Scripts\python -m pip install poetry   # Windows
> .venv\Scripts\poetry install
> .venv\Scripts\poetry run python -m bot.main
> ```

## Запуск через Docker

```bash
# 1. Создать .env из примера и заполнить токены
cp .env.example .env

# 2. (опционально, для воспроизводимых сборок) зафиксировать зависимости
poetry lock

# 3. Собрать и запустить
docker compose up -d --build
```

Данные (SQLite) хранятся в Docker volume `bot_data`.

## Структура проекта

```
bot/
  main.py                    # точка входа: контейнер, middleware, polling
  config.py                  # настройки из переменных окружения (.env)
  container.py               # Container — сборка адаптеров и сервисов
  domain/                    # бизнес-логика
    models.py                # Macros, Food, DayInfo, DaySummary, AddFoodResult
    parsing.py               # разбор цели и форматов ввода, пересчёт КБЖУ
    services.py              # UserService, DayService, FoodService
  infrastructure/            # адаптеры к внешним зависимостям
    db.py                    # SQLite (aiosqlite)
    deepseek.py              # DeepSeek API
  presentation/              # работа с Telegram
    handlers.py              # Router и обработчики сообщений/callback'ов
    keyboards.py             # клавиатуры
    formatting.py            # форматирование вывода
    middleware.py            # инъекция сервисов из контейнера
```
